#slider in Figma

tap or drag the component: the right side shows what happens in the app

A horizontal slider: the fill and the thumb are meters the code moves, the variant is only the state.

Put it on a screen

  1. Assets → the library → drag #slider onto the screen and pick any variant (the app sets the real one).
  2. Wrap it in a frame (Ctrl/Cmd + Alt + G) of the same size and name the frame SLOT: that name is the contract with the app.
  3. Texts in the preview are placeholders: the app writes into the parts named #slider/…. Nothing hidden.

On the screens now

A slot of the slider's size named #<screen>/<name> (#bedroom/dimmer) with an instance of #slider; the thumb marker at x = 0 of the track, its travel the track's width. The app's track_x/track_width are the slot's x and width in the design.

slot name

harry reports a gesture

The finger is on the node named SLOT: harry hit-tests the drawn tree and hands the app Gesture::Down, moves, Gesture::Up with that name.

actions.rs: one match arm, the component decides

harry's gesture is an action of the app like every other (the listener below sends it). The app's apply matches the node name: you add this arm. The component takes the gesture, updates itself (pressed, on or off, the finger's position) and answers with an event when the gesture completed something, None otherwise.
"SLOT" => {
    if let Some(SliderEvent::Changed(value)) = state.slider.on(gesture) {
        let _ = value; // yours: the finger is up; Moving(value) while it drags
    }
}
the component's side: pub fn on(&mut self, gesture: Gesture) -> Option<SliderEvent>
once per app: the listener that turns harry's input into an action (ui_event_listener.rs) 
impl UiEventListener for UiListener {
    fn handle_event(&mut self, event: UserInputEvent) -> HandleEventStatus {
        // everyware_ui::Input groups harry's touch events into Gesture::Down / Move / Up per node
        for (node, gesture) in self.input.feed(&event) {
            let _ = self.actions.send(Actions::CustomAction(HomeAction::Gesture(node, gesture)));
        }
        HandleEventStatus::Consumed
    }
}

state.rs: the component lives in the app's state

One value per place on the screen; it holds what is pressed, chosen, typed. The app owns it, so it survives between frames and the presenter can read it.
use everyware_ui::slider::{Slider, SliderEvent};
use everyware_ui::design::Sizes;

pub struct State {
    pub slider: Slider,
}

frame is where the design puts the slot: let frame = sizes.frame("SLOT") with sizes = Sizes::load(<the .dcf>) at the start; the touch area follows the design.

presenter.rs: state → UI model

After every action the presenter writes the component into its slot: variant, texts, opacities, the transition of the last change.
model.slider = slot("SLOT", &state.slider);

ui_model.rs: what to show, by node name

One field per node in everyware_ui::ui_model! { ... }; the SlotCustomizer turns it into harry's customizations.
slider: Slot = "SLOT" ["SlotCustomizer"];

state is default, pressed or disabled. The value (0..100) moves #slider/fill (a progress bar) and #slider/thumb (a progress marker), display-only, so the thumb follows the finger every frame. on(gesture) answers Moving(value) while the finger drags and Changed(value) when it lifts; the app sends the device the Changed value and may show Moving live. Slider::new(value, track_x, track_width) needs the track's place on the display, because the finger's x is a display coordinate.

Rust API

core/src/slider.rs

pub struct Slider

A horizontal slider over a track at a known place on the display.

pub fn in_slot(value: f32, slot_x: f32, slot_width: f32) -> Self

A slider at value in a slot whose left edge is slot_x on the display and which is slot_width wide: the track is inset TRACK_INSET on both sides (the #slider design). The slot's place comes from the design (everyware_ui::design::Sizes::frame), so a slot moved in Figma moves the touch area with it.

pub fn new(value: f32, track_x: f32, track_width: f32) -> Self

A slider at value, its track at track_x..track_x + track_width on the display.

pub fn on(&mut self, gesture: Gesture) -> Option<SliderEvent>

Applies a gesture: down jumps to the finger, move drags (also outside the slider), up reports the value.

pub fn dragging(&self) -> bool

A finger is on the slider: a value from outside (the device reported one) waits until it is up, or the thumb would jump under the finger.

pub fn value_transition(&self) -> Option<Transition>

How fill and thumb follow the value: short, so the thumb stays under the finger.

pub enum SliderEvent

What a slider reports.

MovingThe value while dragging.
ChangedThe value when the finger went up.

  1. A property, a value or a transition: components.json; the order of props is the order of the variant name.
  2. The drawing: the component set #slider in the Figma library, every variant; the layers the code sets keep their names #slider/<part>, nothing hidden.
  3. The behaviour: the Rust module (Slider; variant() produces the set's variant string); the parts: the harry binding.
  4. Fetch the design into the app and run everyware_ui_test: it fails when a variant or a part the code uses is missing in the design.
Traps
  • A thumb that starts in the wrong place or runs past the end: the marker node is not at x = 0 of its parent, or startX..endX is not the travel.
  • The value changes but nothing moves: the marker must be the shape itself (a rounded rect), not a frame with children.
  • A slider moved to another x in Figma needs the new track_x in the app: everyware_ui_test cannot see it, the finger can.
