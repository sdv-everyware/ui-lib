#bar-chart in Figma

display only: nothing to tap

A row of 24 bars, each with a level and an accent; display only. The app decides what a bar stands for.

Put it on a screen

  1. Assets → the library → drag #bar-chart onto the screen and pick any variant (the app sets the real one).
  2. Wrap it in a frame (Ctrl/Cmd + Alt + G) of the same size and name the frame SLOT: that name is the contract with the app.
  3. Texts in the preview are placeholders: the app writes into the parts named #bar-chart/…. Nothing hidden.

On the screens now

A slot named by the app (#weather/chart on the smarthome panel) of the chart's size with the one instance of #bar-chart; 24 bars drawn, each a progress bar with its accent twin.

slot name

harry reports a gesture

The finger is on the node named SLOT: harry hit-tests the drawn tree and hands the app Gesture::Down, moves, Gesture::Up with that name.

actions.rs: nothing: display only

This component shows data; it takes no gestures.
once per app: the listener that turns harry's input into an action (ui_event_listener.rs) 
impl UiEventListener for UiListener {
    fn handle_event(&mut self, event: UserInputEvent) -> HandleEventStatus {
        // everyware_ui::Input groups harry's touch events into Gesture::Down / Move / Up per node
        for (node, gesture) in self.input.feed(&event) {
            let _ = self.actions.send(Actions::CustomAction(HomeAction::Gesture(node, gesture)));
        }
        HandleEventStatus::Consumed
    }
}

state.rs: the component lives in the app's state

One value per place on the screen; it holds what is pressed, chosen, typed. The app owns it, so it survives between frames and the presenter can read it.
use everyware_ui::bar_chart::BarChart;

pub struct State {
    pub bar_chart: BarChart,
}

// in State::new
bar_chart: BarChart::new([(40.0, false); 24]),
Display only; BarChart::new(bars) takes up to 24 (level 0..100, accent) pairs. The app scales its data to levels and decides which bars are accented.

presenter.rs: state → UI model

After every action the presenter writes the component into its slot: variant, texts, opacities, the transition of the last change.
model.bar_chart = slot("SLOT", &state.bar_chart);

ui_model.rs: what to show, by node name

One field per node in everyware_ui::ui_model! { ... }; the SlotCustomizer turns it into harry's customizations.
bar_chart: Slot = "SLOT" ["SlotCustomizer"];

#bar-chart has one variant, bars=24: #bar-chart/bar/<1..24> are vertical progress bar meters (the level, 0..100), #bar-chart/bar/<i>/accent is the same bar in the accent colour, shown by opacity. BarChart::new(bars) takes (level, accent) pairs; it clamps a level to 0..100 and does nothing else. Scaling data to levels (a day's temperatures to the chart's height) and choosing the accented bars (the hours with rain) is the app's presenter.

harry bindingvendor/sdv-everyware/ui-lib/harry/src/slot.rs:791 the parts of the clone the code sets
  1. A property, a value or a transition: components.json; the order of props is the order of the variant name.
  2. The drawing: the component set #bar-chart in the Figma library, every variant; the layers the code sets keep their names #bar-chart/<part>, nothing hidden.
  3. The behaviour: the Rust module (Bar; variant() produces the set's variant string); the parts: the harry binding.
  4. Fetch the design into the app and run everyware_ui_test: it fails when a variant or a part the code uses is missing in the design.
Traps
  • Fewer than 24 pairs leave the last bars at zero, never hidden: hidden is forever in harry.
