#radio in Figma

tap or drag the component: the right side shows what happens in the app

A group of radio buttons where one option is on; the group owns the selection, each button is a variant.

Put it on a screen

  1. Assets → the library → drag #radio onto the screen and pick any variant (the app sets the real one).
  2. Wrap it in a frame (Ctrl/Cmd + Alt + G) of the same size and name the frame SLOT: that name is the contract with the app.
  3. Texts in the preview are placeholders: the app writes into the parts named #radio/…. Nothing hidden.

One slot per option, 24 × 24 (or the row that holds it) named #<screen>/<group>/<i>, each with an instance of #radio; the label is a text of the screen next to it, not part of the component. The group is the app's: the slots share nothing in Figma.

harry reports a gesture

The finger is on the node named SLOT: harry hit-tests the drawn tree and hands the app Gesture::Down, moves, Gesture::Up with that name.

actions.rs: one match arm, the component decides

harry's gesture is an action of the app like every other (the listener below sends it). The app's apply matches the node name: you add this arm. The component takes the gesture, updates itself (pressed, on or off, the finger's position) and answers with an event when the gesture completed something, None otherwise.
_ if node.starts_with("SLOT/") => {
    // the option from its slot's name: SLOT/1 is index 0
    if let Some(i) = row_of("SLOT", node).and_then(|n| n.checked_sub(1)) {
        if let Some(RadioEvent::Selected(i)) = state.radio.on(i, gesture) {
            let _ = i; // yours
        }
    }
}
once per app: the listener that turns harry's input into an action (ui_event_listener.rs) 
impl UiEventListener for UiListener {
    fn handle_event(&mut self, event: UserInputEvent) -> HandleEventStatus {
        // everyware_ui::Input groups harry's touch events into Gesture::Down / Move / Up per node
        for (node, gesture) in self.input.feed(&event) {
            let _ = self.actions.send(Actions::CustomAction(HomeAction::Gesture(node, gesture)));
        }
        HandleEventStatus::Consumed
    }
}

state.rs: the component lives in the app's state

One value per place on the screen; it holds what is pressed, chosen, typed. The app owns it, so it survives between frames and the presenter can read it.
use everyware_ui::radio::{RadioEvent, RadioGroup};

pub struct State {
    pub radio: RadioGroup,
}

// in State::new
radio: RadioGroup::new(["Off", "Low", "High"]),
One slot per option, SLOT/1, SLOT/2 ...; the group decides which is on.

presenter.rs: state → UI model

After every action the presenter writes the component into its slot: variant, texts, opacities, the transition of the last change.
model.radio_1 = slot("SLOT/1", &state.radio.options[0]);
model.radio_2 = slot("SLOT/2", &state.radio.options[1]);
model.radio_3 = slot("SLOT/3", &state.radio.options[2]);

ui_model.rs: what to show, by node name

One field per node in everyware_ui::ui_model! { ... }; the SlotCustomizer turns it into harry's customizations.
radio_1: Slot = "SLOT/1" ["SlotCustomizer"];
radio_2: Slot = "SLOT/2" ["SlotCustomizer"];
radio_3: Slot = "SLOT/3" ["SlotCustomizer"];

  1. A property, a value or a transition: components.json; the order of props is the order of the variant name.
  2. The drawing: the component set #radio in the Figma library, every variant; the layers the code sets keep their names #radio/<part>, nothing hidden.
  3. The behaviour: the Rust module (Radio; variant() produces the set's variant string); the parts: the harry binding.
  4. Fetch the design into the app and run everyware_ui_test: it fails when a variant or a part the code uses is missing in the design.
Traps
  • The index the app passes to on(index, gesture) comes from the node name (#x/2), not from the layer order: name the options in order.
  • A label inside the component would need #radio/label in every variant; the design keeps labels on the screen.
