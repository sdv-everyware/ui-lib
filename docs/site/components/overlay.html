Overlay is not a Figma set of its own: it is the Rust side of #sheet and of the keyboard dock. open(), close(), is_open(), transition() (the open or close spec from components.json for the change that just happened). A sheet or a dialog is Sheet (sheet.rs), which adds the layout; a sheet with input fields is Form (form.rs).

What the code sets, and how it moves

an overlay over the screen: the variant is the state, harry animates the change with the open/close transitions; one set per overlay in the app's design. The moving parts carry the same animation as the instance: harry gives a variant change's children no animation of their own

Where it lives, how to change it
Figmano set in the design (code only)
Specvendor/sdv-everyware/ui-lib/components.json:20 properties, values, transitions
Rustvendor/sdv-everyware/ui-lib/core/src/overlay.rs:16 Overlay, the state machine
harry bindingnot found the parts of the clone the code sets
  1. A property, a value or a transition: components.json; the order of props is the order of the variant name.
  2. The drawing: the component set <app>-sheet in the Figma library, every variant; the layers the code sets keep their names <app>-sheet/<part>, nothing hidden.
  3. The behaviour: the Rust module (Overlay; variant() produces the set's variant string); the parts: the harry binding.
  4. Fetch the design into the app and run everyware_ui_test: it fails when a variant or a part the code uses is missing in the design.
Traps
  • The app moves the card and fades the scrim from the overlay's state (display-only); it never sets the sheet instance's variant.
