#scrollbar in Figma

display only: nothing to tap

The thumb of a scrolling list: a vertical progress marker along a track, faded in while the list moves.

Put it on a screen

  1. Assets → the library → drag #scrollbar onto the screen and pick any variant (the app sets the real one).
  2. Wrap it in a frame (Ctrl/Cmd + Alt + G) of the same size and name the frame SLOT: that name is the contract with the app.
  3. Texts in the preview are placeholders: the app writes into the parts named #scrollbar/…. Nothing hidden.

On the screens now

A slot of the list's height, 8 wide, beside the list's slot (not inside it: inside, it would scroll away with the rows), named #<screen>/<name>-scrollbar, with an instance of #scrollbar of that height.

impl UiEventListener for UiListener {
    fn handle_event(&mut self, event: UserInputEvent) -> HandleEventStatus {
        // everyware_ui::Input groups harry's touch events into Gesture::Down / Move / Up per node
        for (node, gesture) in self.input.feed(&event) {
            let _ = self.actions.send(Actions::CustomAction(HomeAction::Gesture(node, gesture)));
        }
        HandleEventStatus::Consumed
    }
}

Rust API

core/src/list_view.rs

pub struct ListView

A scrolling list of rows (#list-item by default, any Row).

pub fn horizontal(mut self) -> Self

The same list, scrolling sideways: rows left to right, the finger's x moves it, view_h is the slot's width and pitch a row's width plus gap.

pub fn is_horizontal(&self) -> bool

Whether the rows lie side by side.

pub fn new(rows: impl IntoIterator<Item = R>, view_h: f32, pitch: f32) -> Self

A list of these rows in a slot view_h high, rows pitch apart (row height plus gap).

pub fn rows(&self) -> &[R]

The rows, in order.

pub fn row_mut(&mut self, row: usize) -> Option<&mut R>

A row to change.

pub fn set_rows(&mut self, rows: impl IntoIterator<Item = R>)

Replaces the rows (a new scan). A row with the same key keeps its pressed and selected state, so a tap in progress survives a refresh between its down and its up (a list fed by a topic refreshes at any moment); the scroll stays within the content.

pub fn pitch(&self) -> f32

The row pitch (height plus gap).

pub fn view_h(&self) -> f32

The viewport's height.

pub fn scroll(&self) -> Scroll

Where the content is (for the harry glue, which steps a fling itself).

pub fn scroll_at(&self, now: Instant) -> f32

The scroll at now.

pub fn content_h(&self) -> f32

The content's height (rows times pitch; the gap after the last row stays).

pub fn max_scroll(&self) -> f32

How far the content scrolls at most.

pub fn thumb(&self, now: Instant) -> f32

The scrollbar's thumb: where (0..100) along the track; 0 when nothing scrolls.

pub fn selected(&self) -> Option<usize>

The selected row.

pub fn select(&mut self, row: Option<usize>)

Marks a row as the selected one (none: clears the mark).

pub fn on(&mut self, row: Option<usize>, gesture: Gesture, now: Instant) -> Option<ListEvent>

Applies a gesture: on a row (harry's hit test), or on none (a move or a lift away from every row). A tap on a row chooses it; a finger that moves past the touch slop drags the content; a fast lift flings it; a press on a running fling stops it.

harry bindingnot found the parts of the clone the code sets
  1. A property, a value or a transition: components.json; the order of props is the order of the variant name.
  2. The drawing: the component set #scrollbar in the Figma library, every variant; the layers the code sets keep their names #scrollbar/<part>, nothing hidden.
  3. The behaviour: the Rust module (ListView; variant() produces the set's variant string); the parts: the harry binding.
  4. Fetch the design into the app and run everyware_ui_test: it fails when a variant or a part the code uses is missing in the design.
Traps
  • A scrollbar inside the list's slot scrolls with the content: a slot of its own, next to the list.
  • The marker is the shape itself (a rounded rect with the meter), not a frame with children: harry moves a marker's own shape.
