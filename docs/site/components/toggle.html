#toggle in Figma

tap or drag the component: the right side shows what happens in the app

An on/off switch, Material 3's switch: the value moves the thumb and fades the track, the variant is only the state.

Put it on a screen

  1. Assets → the library → drag #toggle onto the screen and pick any variant (the app sets the real one).
  2. Wrap it in a frame (Ctrl/Cmd + Alt + G) of the same size and name the frame SLOT: that name is the contract with the app.
  3. Texts in the preview are placeholders: the app writes into the parts named #toggle/…. Nothing hidden.

On the screens now

A slot 52 × 32 named #<screen>/<name> (#entryway/light) with an instance of #toggle inside. The marker node sits at x = 0 of the track with its travel as startX..endX; the preview shows the off position.

harry reports a gesture

The finger is on the node named SLOT: harry hit-tests the drawn tree and hands the app Gesture::Down, moves, Gesture::Up with that name.

actions.rs: one match arm, the component decides

harry's gesture is an action of the app like every other (the listener below sends it). The app's apply matches the node name: you add this arm. The component takes the gesture, updates itself (pressed, on or off, the finger's position) and answers with an event when the gesture completed something, None otherwise.
"SLOT" => {
    if let Some(ToggleEvent::Toggled(on)) = state.toggle.on(gesture) {
        let _ = on; // yours: state.toggle.value is the same
    }
}
the component's side: pub fn on(&mut self, gesture: Gesture) -> Option<ToggleEvent>
once per app: the listener that turns harry's input into an action (ui_event_listener.rs) 
impl UiEventListener for UiListener {
    fn handle_event(&mut self, event: UserInputEvent) -> HandleEventStatus {
        // everyware_ui::Input groups harry's touch events into Gesture::Down / Move / Up per node
        for (node, gesture) in self.input.feed(&event) {
            let _ = self.actions.send(Actions::CustomAction(HomeAction::Gesture(node, gesture)));
        }
        HandleEventStatus::Consumed
    }
}

state.rs: the component lives in the app's state

One value per place on the screen; it holds what is pressed, chosen, typed. The app owns it, so it survives between frames and the presenter can read it.
use everyware_ui::toggle::{Toggle, ToggleEvent};

pub struct State {
    pub toggle: Toggle,
}

// in State::new
toggle: Toggle::new(false),
Read the value any time as state.toggle.value (a pub field); state.toggle.set(on) follows the device without a gesture.

presenter.rs: state → UI model

After every action the presenter writes the component into its slot: variant, texts, opacities, the transition of the last change.
model.toggle = slot("SLOT", &state.toggle);

ui_model.rs: what to show, by node name

One field per node in everyware_ui::ui_model! { ... }; the SlotCustomizer turns it into harry's customizations.
toggle: Slot = "SLOT" ["SlotCustomizer"];

state is default, pressed (the thumb stretches under the finger) or disabled. On and off are not variants: #toggle/thumb is a horizontal progress marker the code moves from 0 to 100, #toggle/on the blue track the code fades in, both display-only and animated by the value transition (200 ms). Toggle::set(value) follows the device without a gesture; on(gesture) answers Toggled(bool) on a completed tap.

  1. A property, a value or a transition: components.json; the order of props is the order of the variant name.
  2. The drawing: the component set #toggle in the Figma library, every variant; the layers the code sets keep their names #toggle/<part>, nothing hidden.
  3. The behaviour: the Rust module (Toggle; variant() produces the set's variant string); the parts: the harry binding.
  4. Fetch the design into the app and run everyware_ui_test: it fails when a variant or a part the code uses is missing in the design.
Traps
  • On/off as a variant switches in steps and rebuilds the tree: keep the value on the marker and the opacity.
  • Two toggles on one screen share the part names #toggle/thumb, #toggle/on: each in its own slot, or they move together.
  • A toggle inside a list row switches instead of fading on stock harry (the animation pass read only the global scope): the display_safety series in everyware/patches fixes it.
