tap or drag the component: the right side shows what happens in the app

The screen's one keyboard: an overlay at the bottom with the keyboard component in its slot, open while a field has the focus.

A sheet is an instance of the library's #sheet with the app's content component swapped into its slot: see #sheet.

A plain absolute frame over the screen with an instance of #keyboard-dock (state closed, below the screen's edge) whose slot #<app>/keys holds #keyboard; the last layer of the root so it is above the sheets.

state is closed or open; the dock slides up by the open transition and is 420 px high (KEYBOARD_DOCK_H). KeyboardDock::follow(focused) opens and closes it with the focus; keyboard inside it is the Keyboard state machine. One dock per screen, above every sheet.

A closed dock.

Opens the dock while a field has the focus and closes it when none has: the screen calls it after every action with form.focused().is_some() (or several forms' or'ed).

The dock is open: the keys are on the screen.

harry bindingnot found the parts of the clone the code sets
  1. A property, a value or a transition: components.json; the order of props is the order of the variant name.
  2. The drawing: the component set #keyboard-dock in the Figma library, every variant; the layers the code sets keep their names #keyboard-dock/<part>, nothing hidden.
  3. The behaviour: the Rust module (KeyboardDock; variant() produces the set's variant string); the parts: the harry binding.
  4. Fetch the design into the app and run everyware_ui_test: it fails when a variant or a part the code uses is missing in the design.
Traps
  • An instance placed absolute by itself lands in the root's flow after import: the instance inside a plain frame with absolute positioning.
  • Dialogs centre in the screen minus the dock while it is open: give the presenter the free height (SCREEN.1 - KEYBOARD_DOCK_H).
