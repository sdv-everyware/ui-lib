display only: nothing to tap

The on-screen keyboard: rows of keys with a character each, pressed keys fade a layer; one component, not a set.

Put it on a screen

  1. Assets → the library → drag #keyboard onto the screen.
  2. Wrap it in a frame (Ctrl/Cmd + Alt + G) of the same size and name the frame SLOT: that name is the contract with the app.
  3. Texts in the preview are placeholders: the app writes into the parts named #keyboard/…. Nothing hidden.

On the screens now

Inside the dock's slot (#<app>/keys), an instance of #keyboard; every key's label is a text override (static labels survive a rebuild), the pressed layer is in the component.

slot name

harry reports a gesture

The finger is on the node named SLOT: harry hit-tests the drawn tree and hands the app Gesture::Down, moves, Gesture::Up with that name.

actions.rs: one match arm, the component decides

harry's gesture is an action of the app like every other (the listener below sends it). The app's apply matches the node name: you add this arm. The component takes the gesture, updates itself (pressed, on or off, the finger's position) and answers with an event when the gesture completed something, None otherwise.
// the keys report by their own names, #kbd/<row>/<i>
_ if node.starts_with("#kbd/") => {
    let mut text = String::new(); // yours: the text of the field being edited
    if let Some(outcome) = state.keyboard.on(node, gesture, &mut text) {
        let _ = outcome;
    }
}
the component's side: pub fn on(&mut self, node: &str, gesture: Gesture, text: &mut String) -> Option<Outcome>
once per app: the listener that turns harry's input into an action (ui_event_listener.rs) 
impl UiEventListener for UiListener {
    fn handle_event(&mut self, event: UserInputEvent) -> HandleEventStatus {
        // everyware_ui::Input groups harry's touch events into Gesture::Down / Move / Up per node
        for (node, gesture) in self.input.feed(&event) {
            let _ = self.actions.send(Actions::CustomAction(HomeAction::Gesture(node, gesture)));
        }
        HandleEventStatus::Consumed
    }
}

state.rs: the component lives in the app's state

One value per place on the screen; it holds what is pressed, chosen, typed. The app owns it, so it survives between frames and the presenter can read it.

pub struct State {
    pub keyboard: Keyboard,
}

presenter.rs: state → UI model

After every action the presenter writes the component into its slot: variant, texts, opacities, the transition of the last change.
model.keyboard = slot("SLOT", &state.keyboard);

One field per node in everyware_ui::ui_model! { ... }; the SlotCustomizer turns it into harry's customizations.

#keyboard has no variants: the keys are #kbd/<row>/<i> with /pressed (faded in while down) and /label (the character of the current mode: letters, shift, symbols). Keyboard::on(gesture) takes the key from the node name and answers an Outcome (a character, backspace, done, a mode change); the text itself belongs to the field being edited (Form, InputField). The keyboard sits in the keyboard dock (#keyboard-dock), one per screen.

The key rows with a character on them, top to bottom.

One10 keys.
Two9 keys.
Three7 keys, between Shift and Delete.

pub enum Key

A key of the keyboard.

CharA character key: row and index from 0.
ShiftUpper case for one letter, or the other symbol page.
DeleteRemoves the last character.
Mode123 / abc.
SpaceA space.
DoneFinished with the field.

pub enum Mode

What the keys show.

LowerLower-case letters.
UpperAfter Shift, for one character.
SymbolsDigits and the common symbols.
MoreSymbolsThe other symbols (Shift in Symbols).

pub struct Keyboard

Keyboard state: the mode and which keys are pressed; the text belongs to the field being edited.

pub fn on_key(&mut self, node: &str, gesture: Gesture) -> Option<Key>

Applies a gesture on a key node: the key shows pressed while the finger is on it and is returned when it is released over it.

pub fn on(&mut self, node: &str, gesture: Gesture, text: &mut String) -> Option<Outcome>

Applies a gesture on a key node and, on a tap, the key to text (the field in focus): what the app does with the result is its own (Done: submit). None while the key is held, for a node that is not a key, and for Shift / mode (they only change labels).

pub fn key_nodes() -> Vec<String>

The key nodes of the component, in the order of the layout.

pub fn label_of(&self, node: &str) -> Option<String>

The label the code sets on a key node (the character keys, Shift and mode); None for keys whose label is fixed in the design (Delete, space, Done).

pub fn pressed_target(&self, node: &str) -> f32

Opacity target of the pressed layer of a key node: 100 pressed, 0 not.

pub fn press_transition(&self, node: &str) -> Option<Transition>

How the pressed layer of a key node fades.

pub fn char_at(&self, row: Row, index: usize) -> Option<char>

The character on a key in the current mode.

pub fn label(&self, row: Row, index: usize) -> String

The label of a character key.

pub fn shift_label(&self) -> &'static str

The label of Shift: what pressing it switches to.

pub fn mode_label(&self) -> &'static str

The label of the mode key: what pressing it switches to.

  1. A property, a value or a transition: components.json; the order of props is the order of the variant name.
  2. The drawing: the component set #keyboard in the Figma library, every variant; the layers the code sets keep their names #keyboard/<part>, nothing hidden.
  3. The behaviour: the Rust module (Keyboard; variant() produces the set's variant string); the parts: the harry binding.
  4. Fetch the design into the app and run everyware_ui_test: it fails when a variant or a part the code uses is missing in the design.
Traps
  • Keys report by their own names (#kbd/r1/3): one keyboard on the screen at a time, or the names collide.
  • A label as a renamed inner layer is lost on a variant swap of the dock; labels are text overrides (labelled() in the generator).
