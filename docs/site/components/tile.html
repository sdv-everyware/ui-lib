#tile in Figma

tap or drag the component: the right side shows what happens in the app

A device's card, Material 3's card for a smart home device: a symbol, a title, a subtitle, a value and the device's control; the whole card opens the device.

Put it on a screen

  1. Assets → the library → drag #tile onto the screen and pick any variant (the app sets the real one).
  2. Wrap it in a frame (Ctrl/Cmd + Alt + G) of the same size and name the frame SLOT: that name is the contract with the app.
  3. Texts in the preview are placeholders: the app writes into the parts named #tile/…. Nothing hidden.

On the screens now

A slot of the tile's size (438 x 248) named #<screen>/<device> with an instance of #tile of the right kind. Texts and the control's position in the preview are placeholders.

slot name

harry reports a gesture

The finger is on the node named SLOT: harry hit-tests the drawn tree and hands the app Gesture::Down, moves, Gesture::Up with that name.

actions.rs: one match arm, the component decides

harry's gesture is an action of the app like every other (the listener below sends it). The app's apply matches the node name: you add this arm. The component takes the gesture, updates itself (pressed, on or off, the finger's position) and answers with an event when the gesture completed something, None otherwise.
"SLOT" => {
    if let Some(TileEvent::Opened) = state.tile.on(gesture) {
        // yours: open the device's sheet
    }
}
the component's side: pub fn on(&mut self, gesture: Gesture) -> Option<TileEvent>
once per app: the listener that turns harry's input into an action (ui_event_listener.rs) 
impl UiEventListener for UiListener {
    fn handle_event(&mut self, event: UserInputEvent) -> HandleEventStatus {
        // everyware_ui::Input groups harry's touch events into Gesture::Down / Move / Up per node
        for (node, gesture) in self.input.feed(&event) {
            let _ = self.actions.send(Actions::CustomAction(HomeAction::Gesture(node, gesture)));
        }
        HandleEventStatus::Consumed
    }
}

state.rs: the component lives in the app's state

One value per place on the screen; it holds what is pressed, chosen, typed. The app owns it, so it survives between frames and the presenter can read it.
use everyware_ui::tile::{Tile, TileEvent, TileKind};
use everyware_ui::symbol::SymbolIcon;

pub struct State {
    pub tile: Tile,
}

// in State::new
tile: Tile::new(TileKind::Slider, SymbolIcon::BedDouble, "Bedroom", "Lights").value("65%"),
The whole card is one touch target; the control inside shows the device (state.tile.toggle, .slider, .segmented, .value) and takes no taps: the device's sheet changes it.

presenter.rs: state → UI model

After every action the presenter writes the component into its slot: variant, texts, opacities, the transition of the last change.
model.tile = slot("SLOT", &state.tile);

ui_model.rs: what to show, by node name

One field per node in everyware_ui::ui_model! { ... }; the SlotCustomizer turns it into harry's customizations.
tile: Slot = "SLOT" ["SlotCustomizer"];

harry draws

The clone of the chosen variant in the slot, with the parts set (#tile/pressed fades in while pressed): the picture on the left is what the device shows.

kind is the control the card shows: toggle (a light), slider (a dimmer), segmented (a fan's modes), stepper (a value with minus and plus) or image (a camera's picture); state is default or disabled. Pressed is #tile/pressed faded in. The parts: #tile/title, #tile/subtitle, #tile/value, the symbol stack #tile/symbol/<icon> (one lit), #tile/image, and the control inside: an instance of the Library's toggle, slider or segmented button, which the binding sets as its own (#toggle/thumb, #slider/fill, #segmented/segment-<i>/selected ...).

The card is one touch target and reports TileEvent::Opened; the control in it shows the device and takes no taps. Its layers have the same names in every tile of a screen, so a tap on one could not say which tile it was; the device's sheet changes the value.

  1. A property, a value or a transition: components.json; the order of props is the order of the variant name.
  2. The drawing: the component set #tile in the Figma library, every variant; the layers the code sets keep their names #tile/<part>, nothing hidden.
  3. The behaviour: the Rust module (Tile; variant() produces the set's variant string); the parts: the harry binding.
  4. Fetch the design into the app and run everyware_ui_test: it fails when a variant or a part the code uses is missing in the design.
Traps
  • A glyph that is not in the stack #tile/symbol/* cannot be shown: add it to #symbol and the stack (ui-component skill).
  • Control parts belong to one kind: #toggle/* is only in kind=toggle. The binding marks them optional per kind, so the contract test checks them in that kind's variants.
  • A control that must take taps (a toggle you flip from the dashboard) is its own slot next to a plain card, not inside a tile.
