#icon in Figma

display only: nothing to tap

A 24 px glyph (Lucide) for the slots of other components; display only, no state.

Put it on a screen

  1. Assets → the library → drag #icon onto the screen and pick any variant (the app sets the real one).
  2. Wrap it in a frame (Ctrl/Cmd + Alt + G) of the same size and name the frame SLOT: that name is the contract with the app.
  3. Texts in the preview are placeholders: the app writes into the parts named #icon/…. Nothing hidden.

Inside another component's layer, one instance per glyph the place can show, all at opacity 0 but the preview's; named <part>/<glyph>. Alone on a screen an icon is a plain picture of the design, not a slot.

actions.rs: nothing: display only

This component shows data; it takes no gestures.
once per app: the listener that turns harry's input into an action (ui_event_listener.rs) 
impl UiEventListener for UiListener {
    fn handle_event(&mut self, event: UserInputEvent) -> HandleEventStatus {
        // everyware_ui::Input groups harry's touch events into Gesture::Down / Move / Up per node
        for (node, gesture) in self.input.feed(&event) {
            let _ = self.actions.send(Actions::CustomAction(HomeAction::Gesture(node, gesture)));
        }
        HandleEventStatus::Consumed
    }
}

state.rs: the component lives in the app's state

One value per place on the screen; it holds what is pressed, chosen, typed. The app owns it, so it survives between frames and the presenter can read it.

After every action the presenter writes the component into its slot: variant, texts, opacities, the transition of the last change.

One field per node in everyware_ui::ui_model! { ... }; the SlotCustomizer turns it into harry's customizations.

harry draws

The clone of the chosen variant in the slot, with the parts set: the picture on the left is what the device shows.

icon names the glyph. The set exists so that a list row, a tile or a symbol can show one of many glyphs by stacking instances at opacity 0 and lighting one: harry does not swap a variant inside a list item, so a row's leading icon is a stack of #list-item/leading/<glyph>.

  1. A property, a value or a transition: components.json; the order of props is the order of the variant name.
  2. The drawing: the component set #icon in the Figma library, every variant; the layers the code sets keep their names #icon/<part>, nothing hidden.
  3. The behaviour: the Rust module; the parts: the harry binding.
  4. Fetch the design into the app and run everyware_ui_test: it fails when a variant or a part the code uses is missing in the design.
Traps
  • A glyph that is not in the stack cannot be shown at runtime; add it to the stack (and to components.json for the icon buttons) rather than drawing it on the screen.
  • An instance swap at runtime is a variant change in a list item and is ignored by harry: opacity only.
